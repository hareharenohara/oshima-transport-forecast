# Phase 2 status

Weather models are requested from JMA MSM, ECMWF IFS, and GFS. Marine models are requested from ECMWF WAM and GFS Wave. Each request batches all 11 audited points.

Live validation on 2026-09-28 found that JMA MSM returned missing `wind_gusts_10m` values at required points and ECMWF WAM returned missing wind-wave components. They cannot reproduce all 127 audited features and are excluded from ML inference with explicit failure records. ECMWF/GFS weather combined with GFS Wave produced complete features and model probabilities. No missing value was filled or approximated.

The comparison output includes mean, min, max, range, population standard deviation, configurable agreement class, per-model values, and source failures.

`POST /api/assess` exposes the Phase 2 pipeline. Gemini 3.5 Flash-Lite receives unit-labelled, model-separated conditions for departure, navigation, and arrival together with 3/6-hour changes, previous output, and explicit data gaps. It organizes those facts without making the final decision. Gemini 3.8 Flash then receives the original judgment context, the 3.5 summary, official Tokai Kisen thresholds, the separately-labelled Nakamura public heuristics, ML cancellation tendencies, forecast horizon, and data quality. Its structured result includes official-criteria comparisons and port reasoning as well as operation probability and confidence. Reported official comparisons are rejected unless their value, unit, threshold, and status match the supplied context; material near/reached criteria may not be omitted. Prompt version is `assessment-v5-grounded-criteria`.

Cron preserves the two-stage Gemini design while batching all target services. Every two-hour run first requests per-service summaries, then per-service final assessments. Summary models are attempted once each in the order Gemini 3.5 Flash-Lite → 3.6 Flash. Final models are attempted once each in the order Gemini 3.8 Flash → 3.7 Flash → 3.6 Flash → 3.5 Flash-Lite. HTTP 400/401/403 stops the chain because changing models cannot repair a request or credential error; availability, quota, server, and structured-output failures advance to the next model. The structured response retains each `service_id` and is split back into service-level D1 rows only after validation. Under normal operation this remains exactly 12 primary summary calls and 12 primary final calls per day. An omitted, duplicate, malformed, ungrounded, or fully failed batch never reuses an older Gemini result; the affected run remains explicitly ML provisional. The actual summary and final models are persisted for audit.
