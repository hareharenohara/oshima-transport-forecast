# ABCDの行動指針

新しい予測は `assessment-v24-abcd-japanese-labels` / `grade_scale: abcd-v1`。

| 内部値 | 画面表示 | 行動 |
|---|---|---|
| A | 良好 | 通常の予定で準備 |
| B | 見込 | 注意点と次回更新を確認しつつ準備 |
| C | 注意 | 代替便・日程を準備 |
| D | 困難 | 予定変更を優先して検討 |

根拠でA/BかC/Dを選ぶ。不確実・モデル差・情報不足は欠航の根拠ではない。これらを理由にCへ固定する処理は設けない。Bへ固定する処理も設けない。拮抗時も航路・時間帯に適用される根拠の強さを比較し、選んだ方向の決め手を説明する。不確かさは別軸の確信度で伝える。

一部の気象・海象データが欠けていても残った根拠をAIに渡す。B/Cは両方選べるままにし、欠損のある判定は確信度を下げる。入力にない数値や気象根拠は作らない。予報取得・AI呼び出し自体の障害は評価ランクに変換しない。取得済みの前回予測と更新時刻を保持し、再更新する。内部の失敗状態は残し、AI生成成功とは区別する。予測なしをCに置き換えない。

旧5段階の保存データは変更しない。旧S→新A、旧A→新B、旧C→新C、旧D→新Dは同じ方向の表示変換とする。旧Bは方向を持たないため新B/Cへ機械的に変換せず、次回のAI更新で根拠から再評価する。便・集約はprompt_version、日別はJSON内のgrade_scaleで新旧を区別する。履歴のAI取得失敗を予測履歴の点として描かない。

画面は日別・便別・集約別・履歴を4段階に統一。アセットv47、Service Worker v23。

公開環境へのデプロイと実際のAI呼び出しは、この変更のローカル検証には含まない。

一覧・詳細・集約・日別・履歴の評価は日本語2文字で表示する。良好は青、見込は緑、注意は橙、困難は赤。添付HTMLを参考に、左から困難→注意→見込→良好の4分割表示とし、該当する予測だけを色で強調する。閉じたトップページカードはセグメントのみ。展開時の総評は評価色の薄い背景・バッジ・AIコメントを横に配置する。詳細画面の評価バッジと行動の目安は維持する。予測を切り替える操作にはしない。説明文でも日本語の評価名を使い、API・保存データはA/B/C/Dのままとする。

注意はオレンジ #B75B08、困難は暗めの赤 #A92323。バッジと選択セグメントの文字は白で統一する。
