# 0. この文書の位置づけ

この文書を、本プロジェクトにおける現時点の最上位仕様書とする。

以前の会話、README、旧仕様書と内容が競合する場合は、原則としてこの文書を優先する。

ただし以下の既存成果物については、実装上の詳細仕様として優先する。

- 学習済みモデル
- モデル入力仕様
- モデル入力監査結果
- Cloudflare推論用成果物
- 学習データ作成時のデータ辞書

Codexは、不明点を独自判断で補完してモデル入力定義等を変更しないこと。

実装上どうしても仕様が不足する場合は、

1. 安全な仮実装が可能なら設定値化して実装
2. 判断内容をドキュメントへ記録
3. モデル定義・確率意味・データソースを勝手に変更しない

という順序で進める。

---

# 1. プロジェクト目的

伊豆大島を発着する東海汽船の各便について、

**4日先までの就航見込みを数値で提示するWebサービス**

を開発する。

非営利で提供し、固定費0円または実質0円で長期運用可能な構成を目指す。

最重要目的は、

**就航便を当てることより、気象・海象による欠航リスクを早期に検知すること。**

利用者が、

- 通院
- 出張
- 観光
- 帰省
- 物流
- 日常の移動

などの予定判断を、公式発表より前から行いやすくすることを目的とする。

---

# 2. プロトタイプ対象範囲

対象：

**東海汽船の伊豆大島関連便**

対象船：

- ジェット船
- 大型客船

対象方向：

- 大島行き
- 大島発

対象期間：

**現在から4日先まで**

更新頻度：

**2時間おき**

飛行機はプロトタイプ対象外。

- 課金

# 4. 最終予測の基本思想

最終的な就航見込みは、単一ロジックでは決定しない。

以下を総合する。

1. 過去実績から作成済みの機械学習モデル
2. 東海汽船が公開している安全運航・運航判断基準
3. 中村氏「気象と交通」ホームページに公開されている判断材料
4. 複数の未来気象予報
5. 複数の未来波浪予報
6. 予報の悪化・改善傾向
7. 予報モデル間の一致・不一致
8. 前回予測からの変化
9. Geminiによる総合判断

機械学習モデルの出力値を、そのままサイト上の最終就航確率としない。

# 6. 学習済みMLモデル

モデル入力は監査後、

**127特徴量**

に整理済み。

モデルの目的：

**過去実績から見た気象欠航リスク検出**

モデルは最終判断器ではなく、

**欠航リスクセンサー**

として利用する。

既存評価例：

- 欠航Recall：約90%以上
- 修正版Recall：約92%
- ROC-AUC：約0.93
- PR-AUC：約0.69

欠航見逃し削減を重視しているため、Precisionは低めで誤警報は比較的多い。

# 19. API障害時

```text

↓

↓

```

# 21. 特徴量生成

関数例：

```ts
buildFeatures(service, normalizedForecasts)
```

仕様：

`model_input_specification_127.csv`

を正とする。

127特徴量すべてについて、

- 名前
- 単位
- 時間窓
- 算出方法
- 航路
- 地点
- 欠損時扱い

を一致させる。

---

# 22. 特徴量生成禁止事項

以下は禁止。

- 欠損を無条件に0で埋める
- 名前だけ合わせて計算方法を変える
- 学習時と単位を変える
- 実績値を未来予測に混ぜる
- 実際の到着時刻を使う
- Geminiに127特徴量を推測させる

---

# 23. 特徴量検証

推論前に必ず検証。

- count == 127
- NaNなし
- Infinityなし
- nullなし
- 想定レンジ
- 必須カテゴリ値存在
- 単位整合

異常時は推論を実行せず、

**prediction unavailable**

として扱う。

---

# 24. ML推論

既存Cloudflareモデルを利用。

出力例：

```json
{
  "cancellation_probability": 0.37,
  "operation_probability": 0.63,
  "model_version": "v1"
}
```

モデルバージョンは必ず結果と一緒に保存。

---

# 25. ML確率の意味

ML値は、

**過去の実測・再解析条件と運航実績から学習した気象欠航リスク**

である。

未来予報そのものの精度誤差は含まれていない。

サイトの最終就航見込みとは区別する。

---

# 26. ML説明

可能であれば主要な影響特徴を取得する。

取得できない場合でも、特徴量値と重要度情報からGemini向け説明材料を構築できるようにする。

ML説明を捏造しない。

利用者がサイトを開く。

まず、

**今日〜4日先の「その日全体の就航見込み」と「予想出帆港」**

がカードで見える。

日を展開すると、

**各便の就航見込みと確信度**

が見える。

便をタップすると、

**なぜその予測なのか**

を、

- 推移グラフ
- 風
- 波
- うねり
- ML
- 予報モデル差
- プラス要因
- マイナス要因
- 確信度根拠

から確認できる。

公式運航情報発表後は、

**公式情報を最優先**

する。

予測履歴は残り、

「4日前からどう予測が変化したか」

を確認できる。

PWAとしてホーム画面から起動でき、

必要な人は大きな予測変化や公式情報をPush通知で受け取れる。

# 96. 最重要原則

このシステムで最優先するのは、

**見た目の派手さではなく、予測ロジックの再現性と説明可能性。**

次に、

**スマホで一瞬で状況を理解できること。**

そして、

**詳しく知りたい人には判断根拠まで確認できること。**

予測不能な場合は無理に数字を出さず、

**予測不能であることを正しく伝える。**

これを全実装に共通する原則とする。

# Gemini判断仕様の優先関係

Geminiによる就航見込み、確信度、公式基準比較、出帆港予測の判断については、`docs/gemini-judgment-spec.md`を本書内の従来記述より優先する。127特徴量、学習済みモデル、データソース、単位、モデル入力定義、ML確率の意味は従来どおり変更しない。

# 追補：地点分離ML V2（2026-09-29承認）

ユーザーの明示承認により、V1を削除・置換せず、地点分離V2を追加する。

- V1: 従来の監査済み127特徴量モデル。重み85%。
- V2: V1の航路情報に、大島北・大島西・相模灘中央・浦賀・対岸港の地点別特徴量を加えた192入力モデル。重み15%。
- 合成確率: `0.85 × V1気象欠航確率 + 0.15 × V2気象欠航確率`。
- 確率の意味、目的変数、データソース、単位、JST時間窓は変更しない。
- 岡田側と元町側は海洋APIの返却グリッドが同一であり、海況について別地点として過大解釈しない。
- モデルバージョンは `v2-ensemble-1`、特徴量バージョンは `v1-127+v2-hybrid-1` として保存する。
- V1モデルと旧世代モデルは削除しない。
- 詳細な実験結果と制約は `docs/model/model_v2_experiment.md` を参照する。

## AIプロバイダー運用追補（2026-09-29承認）

- 主系はGroqとし、整理に `openai/gpt-oss-20b`、最終判断に `openai/gpt-oss-120b` を使う。
- Groqは厳格JSON Schemaを使用し、全便を2段階のバッチで処理する。
- Groq失敗時は既存Geminiモデル列へフォールバックする。
- 全AIが失敗してもML予測の生成・保存は継続する。
- AIのプロバイダー、モデル、HTTP状態、実試行数、取得できたトークン使用量を監査ログへ残す。
