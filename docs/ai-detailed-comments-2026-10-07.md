# 詳細コメントと出力枠の保護

2026-10-07。ユーザーは文章100文字・配列2件の制限を不要とし、出力トークンで問題が出ないよう求めました。ローカルで変更し、未デプロイです。

## 説明項目

- プロンプトから100文字制限を削除し、出力スキーマから要因・港理由の `maxItems:2` を削除。
- 総合コメントは気象の具体値、基準比較、モデル差、判断の決め手、結論に至る理由を詳述。港の選択理由と、集約枠内の航路・時間帯の条件差も説明する。
- 要因欄でコメント全文を繰り返さず、同じ説明を二重生成しない。
- 便・集約区分・更新間隔・判定基準・プログラムの確信度計算は変更しない。
- プロンプト版 `assessment-v15-detailed-grounded-comments`。

## 出力上限

文字数・件数の制限を外しても、APIに有限の出力上限は必要です。

1. 初回は1リクエスト1,600トークン。推論分を含みます。
2. 入力の保守的推定とこの出力枠が毎分8,000の枠へ入らない場合は、送信前に対象を分割。出力を1,600未満へ黙って縮めません。
3. `finish_reason:length` は、JSONとして有効であっても途中終了として採用しません。複数評価なら対象を分割して再生成。
4. 単独評価で途中終了した場合は1回だけ最大3,200へ拡大して再試行。毎分制御は実際の利用可能枠に合わせて上限を下げます（最低1,600）。
5. それでも途中終了する場合は評価不可を明示。無限再試行や途中回答の採用、構成便の間引きは行いません。
6. 単独評価の経路にも同じ管理を適用。

毎分待機と、返却usage・finish reason・返却IDの監査は維持します。日次残量の組織全体管理はまだありません。これらの対策は、どんな長さの回答でも必ず完結する保証ではありません。
